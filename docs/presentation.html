Safe Rust port of the Debian/Ubuntu security-audit pipeline with AWS host checks, structured logging, and optional local-model triage.

Why it exists

It replaces a shell/Jenkins pipeline with predictable execution and auditable evidence, while keeping stage logic easy to inspect.

Every command uses explicit argument arrays, fixed PATH, temporary sanitized environment, bounded reads and deterministic timeouts. This removes shell escapes, unbounded pipelines and missing evidence from the original audit flow.

Tests validate every stage, parallel disabled mode, excessive worker values, the runtime prompt and the typed-question contract.

Eleven stages

Each card maps to a first-class stage that can be executed alone, skipped, or excluded via documented false-positive patterns.

precheck

dpkg/apt availability, missing tools, package metadata lock and installation candidates.

docker

Privileged containers, Docker socket mounts (both socket paths), and daemon availability.

clamav

Signature age, temp/container volume scans, scan time bounds and timeout reporting.

debsums

Package checksum mismatches, changed system files, failed integrity checks.

rootkit

chkrootkit/rkhunter rootkit signatures, hidden files, suspicious output and timeouts.

persistence

UID 0 accounts, cron and systemd unit inspection, authorized_keys review and suspicious units.

network

Listening sockets, established connections, and Ubuntu ESM security update detection.

web

SQL injection, Log4Shell, Shellshock, XSS, webshell and sensitive-file probes, brute force, scanner noise.

auth

Failed and successful logins, sudo denials, bursts and break-in indicators.

hardening

Firewall, SSH settings, kernel sysctl coverage, and risky account configuration.

aws

IMDSv1/v2, identity/profile, credential exposure, user-data secrets, agent and NTP state.

Parallel and serial orchestration

Lightweight analyses (web, auth, hardening, aws) can share workers, while heavy stages remain barriers. Canonical report order is restored before notification and publishing.

Security and false-positive controls

  • Explicit argv and fixed PATH; no shell fallbacks.
  • Sanitized environment, bounded output, process-group timeouts.
  • AWS file reads capped at 1 MiB; IMDS calls bypass proxies and have a 2-second cap.
  • Exceptions use --allow-finding, --exceptions-file patterns.
  • Structured JSON events go to stderr, leaving stdout audit-compatible.

Triage and model packaging

The default laya stage runs the Laya typed-decision model in-process against a compact audit summary. The dataset in laya-dataset/ describes that same System One model: every row pairs the audit context with typed notify/severity labels, and a Rust test keeps the question contract aligned. A thin tools/finetune.py wrapper drives Laya's upstream trainer on the multilingual base.
